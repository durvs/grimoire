# Grimoire V1.1 — Referências e Grafo de Dependências — Design Spec

> Data: 2026-06-11 · Status: aprovado em brainstorming
> Extensão do MVP (ver `2026-06-10-grimoire-design.md`): referências léxico-estruturais e grafo de imports, extraídos no mesmo passe de indexação.

## 1. Objetivo

Responder, com custo de tokens mínimo, as perguntas de navegação que agentes fazem o tempo todo:
"quem chama essa função?", "do que esse arquivo depende?", "o que quebra se eu mudar isso?".

## 2. Decisões

| Decisão | Escolha | Racional |
|---|---|---|
| Semântica de referência | Léxico-estrutural: toda ocorrência de identificador (tree-sitter), anotada com def/use e símbolo container | Resolução semântica real exige resolver escopo/imports por linguagem — semanas. O léxico cobre a pergunta do agente; falsos positivos (nomes iguais em módulos distintos) são aceitáveis e visíveis no resultado |
| Imports | Resolver locais para caminhos reais do repo; não-resolvidos do projeto = `unresolved`; pacotes de fora = `external` | Grafo navegável (o agente "segue" o arquivo); externos ainda informam a superfície de dependências |
| Direção inversa | Incluída: `dependents_of(file)` | Consulta inversa na mesma tabela é de graça; é a pergunta mais valiosa ("o que quebra?") |
| Extração | No mesmo passe do chunking — parse ÚNICO por arquivo alimenta chunker e extrator | Custo extra de indexação ~zero |
| Armazenamento | Tabelas LanceDB `refs` e `imports`, sem vetores, incrementais (delete-by-file/re-add, igual `chunks`) | Mesmo motor, mesma incrementalidade, zero infra nova |
| Migração de schema | Manifest ganha `"version": 2`; versão diferente ⇒ drop das tabelas + re-index completo automático | Mecanismo permanente de migração (resolve a pendência da revisão final do V1.0) |
| Linguagens com extração de imports | Python e TS/JS/TSX na V1.1 | Demais linguagens têm refs (identificadores funcionam para todas), só não têm grafo de imports |

## 3. Componentes

### 3.1 `references.py` (novo)

- `extract(rel_path: str, tree, lang: str) -> tuple[list[Ref], list[RawImport]]`
- `Ref = {name, line, kind: "def"|"use", container}`
  - `kind="def"` quando o identificador é o name-child de um node em `DEFINITION_TYPES` (reusado do chunker, incluindo unwrap de `decorated_definition`/`export_statement`)
  - `container` = símbolo da definição mais interna que envolve a ocorrência (`"OrderService.calculateDiscount"`), vazio em nível de módulo
  - Tipos de node considerados identificador: `identifier`, `type_identifier`, `property_identifier`, `field_identifier`, `shorthand_property_identifier` (por linguagem, lista única tolerante)
- `RawImport = {module, line}`
  - Python: `import_statement`, `import_from_statement` (incluindo relativos com `.`)
  - TS/JS/TSX: `import_statement`, `export ... from`, `require("...")`
  - Outras linguagens: lista vazia

### 3.2 Refactor mínimo no `chunker.py`

- Nova função `parse_tree(text, lang)` exposta; `chunk_file` passa a aceitar árvore opcional para não re-parsear
- Nenhuma mudança de comportamento no chunking

### 3.3 `store.py`

- Tabelas novas (sem vetor):
  - `refs(file_path, name, line int32, kind, container)`
  - `imports(file_path, module, line int32, target, status: "resolved"|"external"|"unresolved")`
- `sync()` popula as três tabelas no mesmo loop de arquivos alterados; deleção por arquivo cobre as três
- **Resolução de imports** (em sync, contra o conjunto real de arquivos escaneados):
  - Python: `a.b.c` → `a/b/c.py` ou `a/b/c/__init__.py`; relativos (`from . import x`, `from ..pkg import y`) resolvidos a partir do diretório do arquivo
  - TS/JS: apenas specifiers relativos (`./`, `../`) → tenta `«spec».{ts,tsx,js,jsx}` e `«spec»/index.{ts,tsx,js,jsx}`
  - Specifier não-relativo (TS) ou módulo não encontrado que não pareça local → `external`; parecia local mas não achou → `unresolved`
    - Heurística "parece local": Python = primeiro segmento existe como diretório/arquivo do repo; TS = specifier relativo
- **Versão do índice**: `manifest["version"] = 2`. Em `sync()`, se a versão do manifest ≠ atual: drop de todas as tabelas + manifest zerado ⇒ re-index completo. Índices v1 existentes migram sozinhos na primeira busca.

### 3.4 Tools (`server.py`)

Todas rodam lazy sync antes (mesmo padrão de `search`):

| Tool | Retorno |
|---|---|
| `find_references(symbol, project_path, limit=50)` | Definições primeiro, depois usos: `{file, line, kind, container, line_text}`; lista vazia se nada |
| `dependencies_of(file_path, project_path)` | `{files: [paths], external: [modules], unresolved: [modules]}` |
| `dependents_of(file_path, project_path)` | `[paths]` de arquivos cujo import resolve para o alvo |

`find_references` busca por igualdade exata de `name` (o nome simples do identificador, ex: `calculateDiscount`); o símbolo qualificado do contexto (`OrderService.calculateDiscount`) aparece no campo `container` de cada resultado. `line_text` = conteúdo da linha (trim), para o agente ver o contexto sem abrir o arquivo.

## 4. Tratamento de erros

- Parse quebrado ⇒ arquivo sem refs/imports (chunks já caem para blocks); nunca derruba o sync
- Símbolo/arquivo inexistente nas tools ⇒ lista vazia / dict vazio, não erro
- `file_path` fora do projeto em `dependencies_of`/`dependents_of` ⇒ `ValueError` (mesmo guard do `outline`)

## 5. Testes

- Fixture estendida com imports cruzados reais: `src/orders.ts` importa de `./users` (relativo TS); novo `src/api.py` com `from src.users import validate_cpf`-style (pontilhado) e um import externo (`react` / `fastapi`)
- Extração: def vs use; container correto (uso dentro de método anotado `Classe.metodo`); identificadores em linguagem sem extractor de imports ainda geram refs
- Resolução: relativo TS (com e sem extensão), pontilhado Python, `__init__.py`, externo, unresolved
- Inversa: `dependents_of` acha o importador
- Incremental: editar arquivo substitui refs/imports antigos (sem duplicar); deletar arquivo limpa as três tabelas
- Migração: manifest v1 (sem `version`) ⇒ sync re-indexa do zero sem erro
- Tools via `Client(mcp)` in-memory, incluindo guard de path traversal

## 6. Não-objetivos (V1.1)

- Resolução semântica de símbolos (escopo/aliases)
- Grafo de chamadas (call graph) — refs léxicas já aproximam
- Imports de linguagens além de Python/TS/JS/TSX
- tsconfig paths/aliases (`@/...`) — tratados como external na V1.1
- Atualização da landing (roadmap lá já lista V1.1; marketing fica para o release)
