# Grimoire V1.3 — Memória de Sessão — Design Spec

> Data: 2026-06-12 · Status: aprovado em brainstorming
> `remember()`/`recall()` por projeto, estilo claude-mem: decisões e aprendizados persistem entre sessões, buscáveis semanticamente.

## 1. Objetivo

Agentes esquecem tudo entre sessões. A V1.3 dá ao agente um lugar para gravar decisões não-óbvias, aprendizados e contexto de projeto ("decidimos serializar sync por lock", "o cliente prefere pt-BR nos commits") e recuperá-los semanticamente na sessão seguinte.

## 2. Decisões

| Decisão | Escolha | Racional |
|---|---|---|
| Anatomia | Texto livre + `kind ∈ {decision, learning, context, todo}` + âncoras de arquivo opcionais | Tipo permite filtrar; âncoras ganham staleness automática (digest, mecanismo das regras) |
| Recall | `recall(query)` dedicado reusando `hybrid_search` filtrado a memórias + boost de recência; espelho no `search` geral; `memories()` para listar | Zero infra nova de busca; relevância manda, recência desempata |
| Boost de recência | `score × (1 + 0.25 / (1 + idade_dias))` | Suave: empate de relevância vai para a mais nova; não soterra relevância |
| Espelho | UMA vez no `remember` (chunk `kind="memory"`, `language="memory"`, `symbol="memory:<id>"`, `file_path=""`); removido só no `forget` | Texto da memória nunca muda com o código — sem re-espelho no sync. `file_path=""` fica fora de todo ciclo de vida de arquivo |
| Arquivo deletado | NÃO apaga a memória; âncora vira `missing` | Decisões sobrevivem ao código que as motivou |
| Dedup | `id = sha256(texto)[:12]`; re-lembrar o mesmo texto = upsert (atualiza data/âncoras) | Idempotente |
| Proatividade | Instructions do server + docstrings orientam: recall ao começar, remember ao decidir | Máximo alcançável por um MCP server; hooks são do cliente |
| Versão | 0.4.0; sem bump de INDEX_VERSION (tabela nova via `exist_ok=True`) | Memórias sobrevivem a upgrades |

## 3. Tools

### 3.1 `remember(project_path, text, kind="context", files=None) -> dict`

- Valida: `text` não-vazio; `kind` no enum; cada item de `files` passa pelo guard de path e existe no manifest (erro claro por problema)
- Grava na tabela `memories` com `created_at` UTC ISO e `anchors_json = [{file, digest_atual}]`
- Espelha no índice de busca (uma linha `kind="memory"`); persistência primeiro, espelho depois (falha de embedding não perde memória — recuperável via re-`remember`)
- Retorna `{id, updated: bool}` (updated=true quando upsert de texto existente)

### 3.2 `recall(project_path, query, top_k=5, kind=None) -> list[dict]`

- `hybrid_search(store, query, top_k=top_k*3, language="memory")` → join com a tabela por `symbol="memory:<id>"` → filtro por `kind` se dado → re-rank com boost de recência → top_k
- Resultado: `{id, text, kind, created_at, age_days, score, anchors: [{file, stale|missing}]}`

### 3.3 `memories(project_path, kind=None) -> list[dict]`

Listagem completa, mais recentes primeiro, mesmo shape do recall (sem score).

### 3.4 `forget(project_path, memory_id) -> dict`

Remove tabela + espelho. Id inexistente → `{deleted: false}`.

## 4. Armazenamento

Tabela `memories` (sem vetor): `id, text, kind, created_at (ISO str), anchors_json (str)`.
Staleness por âncora derivada na leitura: digest da âncora ≠ manifest ⇒ `stale`; arquivo fora do manifest ⇒ `missing`. Nada é gravado na manutenção.

## 5. Instructions (server)

Acrescentar às instructions do FastMCP: "Ao começar a trabalhar num projeto, chame `recall` com o tema da tarefa. Ao tomar uma decisão não-óbvia ou aprender algo que não está no código, grave com `remember`." README ganha sugestão de linha para CLAUDE.md do usuário.

## 6. Tratamento de erros

- `remember` com kind inválido / âncora fora do projeto / âncora não indexada ⇒ ValueError com mensagem acionável
- `recall`/`memories` sem memórias ⇒ lista vazia
- `forget` inexistente ⇒ `{deleted: false}`

## 7. Testes

- Upsert por texto (mesmo texto duas vezes → 1 memória, data atualizada); ids distintos para textos distintos
- Recall semântico via fake_embed; boost de recência: duas memórias de relevância ~igual → mais nova primeiro
- Âncora stale após editar o arquivo; âncora `missing` após deletar (memória preservada)
- Espelho aparece no `search` geral com `kind="memory"`; `forget` remove dos dois lugares
- Validações de `remember`; fluxo completo via Client in-memory
- Versão 0.4.0 no smoke

## 8. Não-objetivos

- Hooks/auto-injeção em session start (cliente)
- TTL/expiração e consolidação automática de memórias
- Memória cross-projeto
- Edição (forget + remember cobre)
